## Reviewed boundaries

- **Frontend HTML:** `frontend/water-leak-guard-card.js` uses `innerHTML` for static templates and composed fragments. Dynamic entity states, names, configuration, event labels, identifiers and error messages use `esc`; numerical chart/style values use numeric parsing and fixed ranges. Event handlers are attached in JavaScript. No external script/image URL configuration or direct external API request is used by this card. Navigation targets are fixed HA routes. Existing card tests exercise escaped recipient names, malformed state shapes and rendering failures.
- **WebSockets and native actions:** authenticated HA connections are required. Card actions resolve the current active user's normal login, then pairing, current recipient permissions and Home state are checked again inside the serialized writer. Long-lived tokens, inactive/system users and stale pairings are rejected. External reset also binds source generation, active event and reset nonce. Tokens/nonces are not returned through the card WebSocket or public state attributes.
- **Native HA controls:** ordinary HA services and detector switch entities remain controlled through Home Assistant's normal account/service permissions. Card pairing is not a replacement for securing HA accounts or native control access. Bypass and learning-reset services intentionally remain available as native automation controls.
- **Credentials:** no embedded real private key, GitHub token, AWS access key or JWT was found by the targeted working-tree scan. Recipient bearer tokens and reset nonces are generated by the integration, checked against current state, and intentionally carried in Companion notification action data. HA config/storage, backups and the configured notification service are trusted and may contain those values. The card does not receive them.
- **Files and paths:** HA Store keys derive from the integration domain and HA-generated config-entry IDs. Static card files are fixed paths. Corrupt-store discovery is restricted to the exact escaped Store filename and already runs in the executor. Card content hashing and HA Store I/O use asynchronous/executor APIs. WLG-01 closes the direct metadata I/O found on startup.
- **External data:** non-finite/negative measurements, timezone-free timestamps, changed source identities, replayed/out-of-order MQTT measurements and invalid persisted safety containers are rejected or quarantined. MQTT payload parsing is bounded to 65,536 bytes and depends on the supported HA adapter; missing evidence fails closed. Notification external-reset action payloads have a 4,096-character bound. HA event bus access and the configured MQTT broker are trusted inputs requiring their own access controls.
- **Dependencies/network:** the integration manifest has no third-party runtime requirements. Python imports are standard library or supplied by the supported Home Assistant installation. The bundled card has no npm runtime dependency. HA provides MQTT, authentication, storage and notification transport; this repository does not implement a custom HTTP/TLS client or disable TLS validation. Known-vulnerability coverage of the complete user's Home Assistant installation requires auditing that actual installation and is outside this repository's empty runtime dependency list.
